description: Product audience and concurrent-editing boundaries supplied by the user.

Fade turns the teacher's spoken task into short steps on each student's screen, with a voice that helps them. It is built for students with learning differences including ADHD, dyslexia, and autism.

**Why:** The user identifies calm, large-text, low-clutter, high-contrast presentation and one highlighted task at a time as core accessibility requirements.

**How to apply:** Keep student-facing guidance focused and supportive; do not use the word “wrong” in the student experience.

The user says, “Each person owns their own files. Don't edit the other person's files.” Concurrent student-side work is limited to the student page and new student-only files; server, teacher, and shared socket code belong to the other collaborator.

**Why:** Two people edit the same application at once, so changing shared files risks overwriting the collaborator's work.

**How to apply:** Confirm current ownership before expanding a future request beyond student-only files. Do not change shared files to simplify student-side integration.
